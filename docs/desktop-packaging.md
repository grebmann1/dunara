# Desktop packaging and updates

`pnpm build && pnpm desktop:package` produces a local macOS candidate under `.builder/desktop-packages/`. Build on the target architecture with Node 24 and pnpm 11.13.1. The candidate includes the locked production dependencies, compiled Studio/runtime, a SHA-256-checked official Node distribution with npm, Playwright's headless Chromium, and the pinned Codex image runtime. No source profiles, app workspaces, credentials or Git history are packaged.

The default candidate uses ad-hoc signing for local qualification. It is not a notarized public installer. `pnpm desktop:package --release` requires a clean source commit and explicit Apple notarization configuration, and requires Developer ID signing. It creates DMG/ZIP artifacts and update metadata without publishing. Inspect `desktop-receipt.json`, qualify the exact files and retain their hashes before a separate release step. Build and qualify each architecture independently.

At first launch, an installed app asks for an app workspace and authorization for local builds. Its profile is saved under the existing **Mobile App Builder** application-data identity. It does not move or discover source-checkout profiles automatically. Existing explicit `--workspace`, `--home` and `--user-data` launches continue to use those exact locations. Retain all three paths together when resuming an existing profile; never run two owners against the same profile. Keychain identity and encrypted credential contexts are unchanged.

**Dunara → Check for updates** checks the public release channel only on request. Downloads and restart/install have separate choices. Auto-download, installation on ordinary quit, prereleases and downgrade are disabled. Before installing, the desktop stops its own backend; no Assistant turn or preview is automatically retried after restart. Electron's macOS updater validates signatures. An unavailable or unqualified release channel produces recovery guidance and leaves the installed app unchanged.

Qualification must include a packaged launch without a source checkout or system Node, a generated Expo preview, image-runtime discovery, captures, remembered settings across quit/relaunch, source ZIP recovery, signature/notarization validation, and a signed previous-version → next-version update preserving a disposable profile. A source launch or generated DMG alone does not establish installer/update qualification. Physical-device and store-submission checks remain separate.
